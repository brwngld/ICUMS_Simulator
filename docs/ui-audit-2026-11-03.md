# UI audit — popups, buttons, navigation, field highlights

**2026-11-03 · dark theme · desktop 1440×900 · in-app browser against the dev server**

Scope: student and instructor surfaces walked end to end (sign-in → dashboard → builder →
programme/course/module workspaces → lesson editor → Demonstration Studio → journey organizer →
learner roadmap/course overview → simulator portal → account settings). Findings only — **no code,
stylesheet, template, or copy was changed** (theme/copy lock). Screenshots were captured during the
walk; every claim below is reproducible.

Not covered: light theme, mobile/narrow widths, Django admin, and the BOE practice desk
(blocked by finding 1).

---

## P1 — Broken pages and visible junk

### 1. The practice desk 500s: pending migrations (blocks the simulator)
`GET /test/` → **OperationalError: no such column: `scenarios_ucrdeclaration.demonstration_session_id`**.
The working tree contains four unapplied migrations:

```
hybrid.0010_demonstrationsession_demonstrationevent_and_more
hybrid.0011_demonstrationsession_last_activity_at_and_more
scenarios.0052_alter_ucrdeclaration_options_and_more
scenarios.0053_alter_ucrdeclaration_demonstration_session
```

`python manage.py migrate` fixes it — but that changes the dev database, so it needs your go-ahead.
Until then every desk/UCR-touching page is a hard error page.

### 2. Raw template comments rendered as page text (two pages)
Django only strips `{# … #}` comments that are **single-line**; a multi-line one passes through
verbatim. Both defects are multi-line comments:

- **Instructor dashboard** (`/instructor/`): under the Student progress table, the literal text
  `{# One dialog per multi-programme student, held after the table so no dialog sits inside a cell. … #}`
  — `templates/instructor_portal/dashboard.html:109-110`.
- **Simulator chrome** (every page using `base_simulator.html` without service areas — e.g.
  `/practical/portal/`): the header shows
  `{# Every service area is gated behind simulator access, so offering them here would only be a page of bounces. #}`
  — `templates/core/base_simulator.html:155-156`.

Fix is mechanical (make each comment one line, or use `{% comment %}`); the visible text disappears,
so per the lock I'm treating the intended outcome as needing your OK.

## P2 — Invisible icons and unstyled buttons

### 3. Two icon names don't exist → empty slots
`templates/components/icon.html` defines 28 icons. Templates reference two names it does not define,
so the SVG renders with no paths — a blank 36px box:

| Template | Line | Missing name | Where it shows |
|---|---|---|---|
| `templates/hybrid/course_detail.html` | 39 | `assignment` | Course workspace "Items to resolve" stat card |
| `templates/hybrid/module_detail.html` | 43 | `assignment` | Module workspace "Not publish-ready" stat card |
| `templates/core/my_programmes.html` | 18 | `menu_book` | Student "My programmes" card |

The other three stat cards on the same pages render fine, so the empty slot reads as a glitch.

### 4. Journey organizer: Save/Delete render as bare text
On `/instructor/hybrid/journeys/<id>/` the "Save workflow" and "Delete workflow" buttons (and the
page's card/label styling generally) come out unstyled — transparent background, light-theme border,
i.e. they read as plain text lines. Root cause: `templates/hybrid/journey_detail.html:4` loads only
`css/hybrid-builder.css`, but the base `.authoring-primary/.authoring-secondary` button system lives
in `css/instructor-theory-builder.css` (every other authoring page loads it). Fix: add the missing
stylesheet link to that template.

## P3 — Field focus/highlight: three different systems (your "not done properly")

| Surface | What focus looks like | Source |
|---|---|---|
| Sign-in page, student Settings | **Nothing** on mouse click — outline `none`, border unchanged. Keyboard users do get a yellow ring (`:focus-visible`) | `app.css:13,31,85` define the system, but no `:focus` rule survives on these pages |
| Instructor authoring surfaces (forms, dialogs) | **3px translucent purple ring** drawn *outside* the field — doubles with the field border and **overlaps the helper text below** (clearly visible in the Add-course dialog: the ring cuts through "Shown to instructors and learners across the programme.") | accent `color-mix(… transparent 45%)` ring from `app.css:31` + tight helper spacing |
| Simulator portal cargo search | The only **accent-filled input** in the app (`rgb(43,40,96)` background) — reads as a permanently highlighted field | deliberate-looking, but inconsistent with every other input |

Related inconsistencies:
- The disclaimer checkbox uses the **native browser tooltip** ("Please check this box if you want to
  proceed.") — OS-styled, unlike the app's own dialogs/messages.
- Buttons and inputs disagree: buttons show a visible focus ring; text inputs (mouse focus) show none.

## P4 — Navigation defects

### 5. Multiple sidebar items marked active at once — including a dead link
On the learner course overview (`/theory/courses/…`) **three** sidebar entries carry the `active`
class simultaneously: Dashboard (`/`), Learning Roadmap (`/theory/`), and **"Assessments", whose
href is `#` — a dead entry that is visible to every student and receives active styling**. The same
dead `#` Assessments link exists in the instructor sidebar. Two problems in one: the highlight logic
marks several items active, and a placeholder link ships in the nav.

### 6. Simulator portal chrome: three "auth" links all look active
`Login`, `Forgot Password?`, `Request Account` (plus Student dashboard and Workspace home) all render
with active-style backgrounds at once on `/practical/portal/`. If this chrome is deliberate
real-ICUMS mimicry, the triple highlight still reads as broken — needs a ruling.

### 7. Course builder table headers wrap letter-by-letter
`/instructor/courses/?path=theory`: the MODULES and LESSONS columns render as "MO DUL ES" / "LES SON S"
(column too narrow for its uppercase header). Actions cell also wraps its four buttons to two rows.

### 8. One page, three names
Sidebar "Theory builder" → breadcrumb "Course builder" → heading "Manage Courses" (and the page lists
*programmes*, which `docs/product-rules.md:39` calls "courses"). Terminology ruling needed
(this is the same ambiguity flagged as D11 in the lesson-reference plan).

## P5 — Popups

- **What works well**: the hybrid `<dialog>`-based popups (Add course / Add module) are centered,
  blurred-backdrop, close via × / Cancel / Esc, and the Demonstration Studio's recording buttons
  enable/disable correctly by state (Start → Pause/Stop → Clear) with a status banner.
- **Rich-text editor Link/Image use `window.prompt`/native dialogs** (`static/js/rich-text-editor.js:618,640`):
  OS-styled popups inconsistent with the app's dialog system, and they silently no-op in embedded
  webviews (confirmed: no dialog surfaced inside the Demonstration Studio context). An in-app link
  dialog would also enable the later "reference picker" idea from the library plan.
- **Service-area tab rail** (recent restyle, seen via the studio's embedded desk view): functional,
  but the last tab truncates ("Post Clear…") behind the `›` scroll arrow at narrow widths.
